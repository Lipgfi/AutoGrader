# B3 题库管理模块问题汇总

## 1. 数据库与 B4 分离
- **问题**: B3 默认使用独立数据库 `autograder_b3`，与 B4 主数据库 `autograder` 分离
- **影响**: B4 中发布作业引用的题目（如 Q01），B3 中不存在；B3 内置的题目（Q02-Q10），B4 作业未使用
- **修复**: 已为 B3 配置 `.env` 指向 B4 主数据库地址

## 2. 依赖 Linux Shell 环境
- **问题**: B3 的评测使用 Docker 沙箱或本地 shell 执行，依赖 Ubuntu/Linux 环境
- **影响**: Windows 上无法运行真实评测，`evaluate` 接口在执行 shell 命令时会崩溃
- **状态**: 无解（当前 Windows 环境），需迁移到 Linux 或 WSL

## 3. Python 3.14 兼容性问题
- **问题**: `pydantic-core` 依赖的 `pyo3` 最高支持 Python 3.13，当前环境为 Python 3.14
- **修复**: 通过 `PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1` 可强制安装，但可能导致不稳定

## 4. `_question_blueprint` 返回空字典导致 NoneType 报错
- **问题**: B4 数据库中的题目（如 Q01）不在 B3 的 `QUESTION_BLUEPRINTS` 种子数据中，`_question_blueprint` 返回 `{}`
- **影响**: `metadata_json` get 到的默认值 `{}` 在后续逻辑中可能导致 KeyError 或空迭代
- **修复**: 已改为返回 `{"allowed_commands": [], "metadata_json": {}}`

## 5. B3 题目 ID 与 B4 题目 ID 不重叠
- **问题**: 
  - B4 数据库中有 `Q01`（邮件发送作业, shell），B3 种子数据无此题目
  - B3 种子数据有 `Q02-Q10`、`API_DEMO`，B4 数据库无记录
- **状态**: 已共库后 Q01 可被 B3 访问，但 Q02-Q10 需手动导入到 B4

## 6. B3 端口冲突
- **问题**: Windows 上 8003 端口被占满（两个进程同时监听），导致重启失败
- **影响**: 修改代码后无法热重启，需手动杀进程
- **状态**: 需关注的重启问题

## 7. 题目测试用例为空的评测行为
- **问题**: Q01 原本在 B4 数据库中无测试用例，B3 评测返回 `total_count: 0, score: 0`
- **修复**: 已为 Q01 添加测试用例（预期答案：`echo "作业提交内容" | mail -s "20250001_第1次作业" linuxos_assignment@163.com`）

## 8. 安全静态检查拦截合法命令
- **问题**: `security_checks.py` 中的 `DANGEROUS_TOKENS` 包含了 `curl`、`mail` 等常用命令被标记为危险
- **影响**: Q01 题目的 `mail` 命令可能被安全扫描拦截（B3 评测时通过 `allowed_commands` 白名单控制）
- **状态**: 需为 shell 类型题目正确配置 `allowed_commands`

## 9. 脚本题硬编码答案拦截
- **问题**: `scan_script_code` 对 Q10 脚本题会检查最终输出是否硬编码，但此检查依赖于含有特定输出字符串 `expected`，逻辑较脆弱
- **状态**: 待优化

## 10. B3 评估记录存储
- **问题**: B3 的 `evaluation_records` 等表存储在自身数据库，共库后与 B4 的 `submissions` 表存在冗余
- **状态**: 架构可优化

## 11. Docker 沙箱不可用
- **问题**: Windows 环境下 Docker 桌面版可能不可用，B3 配置 `SANDBOX_BACKEND=auto` 回退到本地子进程
- **影响**: 本地子进程在 Windows 上无法执行 shell 命令
- **修复**: 已将 `.env` 配置为 `SANDBOX_BACKEND=local`

## 12. B3 路由前缀与 B4 不一致
- **问题**: B3 所有接口使用 `/api/v1/b3/` 前缀，前端需单独配置代理规则
- **影响**: 增加了前端代理配置复杂度
